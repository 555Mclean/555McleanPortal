Sponsor Slots

How to turn on the portal's advertising section — and what to expect from it before you do.

Ads are off until the board turns them on. With data/ads.json in its shipped state, no ad script loads, no section renders, and the page is byte-for-byte what it was before this feature existed. Nothing here happens by accident.

1.Set expectations first

This is worth reading before anyone spends an evening on the AdSense signup.

  • The revenue will be very small. Display ads pay roughly $1–$5 per thousand page views. A portal serving one building realistically sees a few hundred views a month, so the honest estimate is single-digit dollars per year, and AdSense does not pay out at all until the balance reaches $100.
  • Approval is not guaranteed. AdSense reviews each site and generally wants substantial, original, publicly useful content. A resident portal on a GitHub Pages sub-path is an uncertain candidate.
  • ads.txt cannot be served from this repo. AdSense looks for it at 555mclean.github.io/ads.txt — the domain root — but this site is a project page published under /555McleanPortal/, so it can only publish files beneath that path. Expect a permanent “missing ads.txt” warning in the AdSense dashboard unless the co-op buys its own domain and points it at the site.
  • Ads bring third-party tracking onto a page residents use to read building notices. Google sets advertising cookies and, in some regions, must show a consent prompt. Consider whether the board wants that on a shareholder site for a few dollars a year.

If the goal is to offset costs, note that the portal's actual hosting cost today is $0 — GitHub Pages is free for this repo.

2.Get the AdSense ids

  1. Sign up at adsense.google.com with the board's Google account and submit https://555mclean.github.io/555McleanPortal/ as the site.
  2. Wait for approval (typically a few days to a few weeks; it can be declined).
  3. Once approved, note your publisher id — it looks like ca-pub-1234567890123456.
  4. Create one display ad unit, set it to Responsive, and note its slot id — a 10-digit number.

3.Fill in data/ads.json

Edit the file, commit, and the next deploy publishes the section. All three of enabled, client, and a unit slot must be real — if any one is missing or still a placeholder, the build treats ads as off and renders nothing.

{
  "enabled": true,
  "client": "ca-pub-1234567890123456",
  "eyebrow": "Supporting the Portal",
  "heading": "Local Sponsors",
  "blurb": "Advertising on this page helps offset the cost…",
  "disclosure": "Advertisement · served by Google AdSense…",
  "units": [
    {
      "id": "sponsors-main",
      "slot": "9876543210",
      "format": "auto",
      "responsive": true,
      "label": "Sponsors section advertisement"
    }
  ]
}

The build log tells you which state you are in — ads: 1 unit(s) when live, or ads: off (no publisher id) when something is still missing.

To add a second placement, append another object to units with its own AdSense slot id.

4.What residents see

  • A Local Sponsors section between the parking waitlist and the About & Contact section, plus a Sponsors link in the top navigation.
  • The section is hidden until an ad actually loads. If the ad is blocked, unsold, or the script fails, residents see no empty box and no “Sponsors” nav link — the page looks exactly as it does today.
  • A disclosure line under every ad stating it is served by Google and is not a board endorsement. Keep it: it is the honest signal to shareholders that the board does not vouch for whoever appears there.
  • Nothing prints — ads are excluded from the print stylesheet.

5.Turning ads back off

Set "enabled": false in data/ads.json and commit. The next deploy removes the ad script, the section, and the nav link entirely — there is nothing else to undo.
